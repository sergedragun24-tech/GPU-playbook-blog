# Глоссарий проекта

Обязателен к открытию наравне с продуктовой справкой при любой работе со статьей. Фиксирует решения по терминам, принятые в уже сданных статьях, чтобы они не расходились между текстами.

Колонка «Статус»: **принято** — решение подтверждено на приемке статьи, применять без обсуждения. **предложено** — вариант выбран по умолчанию, требует подтверждения на ближайшей приемке. **спорно** — найдено расхождение между записанными решениями, применять нельзя до ответа пользователя.

## 3. Механизмы разделения GPU

Источник: статья «PCIe Passthrough vs MIG vs vGPU».

| Решение | Статус |
|---|---|
| MIG — аппаратное разделение ускорителя | принято |
| vGPU — программное разделение, два режима: time-sliced и MIG-backed | принято |
| MIG-backed vGPU — vGPU поверх MIG-инстансов, не поверх целого GPU | принято |
| PCIe Passthrough — режим и функция гипервизора, не технология NVIDIA | принято |
| time-sliced описывается через «кванты времени» и планировщик vGPU | принято |
| MIG и vGPU не описываются одной фразой как взаимозаменяемые | принято |

### Имена профилей

| Решение | Статус | Примечание |
|---|---|---|
| Имя профиля vGPU: карта, объем видеопамяти, буква класса (A30-6C, L40S-8Q) | принято | схема для time-sliced |
| Имя профиля MIG-backed vGPU: карта, число частей вычислительных блоков, объем, буква (A30-1-6C) | принято | средняя цифра — число частей вычислительных блоков |
| Имена вида 1g.6gb, 3g.71gb относятся к MIG на уровне GPU, не к профилям vGPU | принято | в статьях про vGPU не смешивать две схемы |
| Буквы классов: C — вычисления, Q — рабочие станции, B — рабочие столы, A — приложения | принято | |

## Правило пополнения

Глоссарий пополняется после приемки каждой статьи, до закрытия задачи. Порядок:

1. По журналу решений сданной статьи выписать все термины и формулировки, по которым принималось решение.
2. Сверить с этим файлом. Новое — добавить со статусом **принято** и указанием статьи-источника в примечании.
3. Расхождение с уже записанным решением — не переписывать молча. Показать обе формулировки и спросить, какая остается. Спрашивать всегда, в том числе когда новый вариант выглядит очевидно лучше. До ответа решению ставится статус **спорно**.
4. Статусы **предложено**, затронутые в сданной статье, перевести в **принято** или заменить.
5. Записать правку в этот файл в том же ходе, не откладывая. Файл перед записью открывать заново: его могли изменить в другом прогоне, и запись поверх старой копии стирает чужие решения.

Любой новый термин, по которому в этом файле решения нет, выносится на согласование до того, как попадет в текст. Вариант по умолчанию не выбирается молча.

Шаг 2 ветки A и шаг 1 ветки B пайплайна не считаются выполненными, пока этот файл не открыт.
